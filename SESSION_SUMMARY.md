# Session summary and handover — tabular foundation model comparison

Last updated 2026-09-30. Written so that a future Claude Code session can add models to this comparison without
re-discovering how it is built. **Read this file first**, then `data/SCHEMA.md`.

## 1. What this folder is

A self-contained comparison page (`index.html`, no server or external dependency) of every tabular foundation model
(TFM) whose TabArena entry scores at least as high as TabICLv2, with hand-curated fact sheets (architecture, pretraining
and synthetic priors, ICL mechanics, limits, speed/cost, licenses) plus TabArena and TALENT numbers.

- TabArena snapshot: **TabArena-v0.1.9.3**, retrieved 2026-09-30 (view: Models only · all repeats · with imputation).
- TALENT: 48 tables from 7 sources, 8 flagged `headline` (= default columns).
- Folder was renamed from `tfn_comparison` to `tfm_comparison` on 2026-09-30; the Claude memory directory moved with it

## 3. Layout and pipeline

```
index.html                  the page: HTML + CSS + JS, reads data/compiled.js (works from file://)
CLAUDE.md                   short pointer to this file for future sessions
README.md                   user-facing description and how to extend
SESSION_SUMMARY.md          this file
data/
  SCHEMA.md                 field-by-field definition of a model record (incl. optional tabarena_self_reported)
  models/<id>.json          one hand-curated record per model  ← the thing to add / edit
  tabarena.json             GENERATED from data/raw/tabarena/*.csv by scripts/build_tabarena.py
  talent.json               TALENT results, one table per (source, metric, task scope); results keyed by model id
  compiled.js / .json       GENERATED by scripts/build.py; index.html loads compiled.js — never edit by hand
  raw/tabarena/*.csv        leaderboard CSV exports (all subsets + win-rate matrix + Pareto points)
  raw/tabarena_version_history.md   copy of the leaderboard's Version History; its "Current Version:" line feeds tabarena.json
  raw/tabarena_leaderboard_2026-09-23.md   first page-text snapshot (historical)
scripts/
  fetch_tabarena.sh         download current CSVs from the TabArena Space repo, then run build_tabarena.py
  build_tabarena.py         CSV -> data/tabarena.json (entries per subset, licenses, win rates)
  build.py                  models + tabarena + talent -> data/compiled.js (+ .json); prints notes/warnings
  validate_models.py        schema / enum / numeric / join checks for every record + talent.json sanity
.claude/launch.json         "site" config: python3 -m http.server 8765 on this folder (for browser preview)
```

Pipeline: `fetch_tabarena.sh` → `build_tabarena.py` → (`data/models/*.json`, `data/talent.json`) → `build.py` → `index.html`.

## 4. How to add a new model (checklist)

1. **Refresh the leaderboard.** `bash scripts/fetch_tabarena.sh` downloads the CSVs from
   `https://huggingface.co/spaces/TabArena/leaderboard/tree/main/data/entrants_models/imputation_yes/splits_all/<tasks_*>/<datasets_*>/website_leaderboard.csv`
   (HF resolve URLs; the leaderboard's own web table is a Gradio app and harder to scrape). Then open
   `https://tabarena-leaderboard.hf.space`, expand "Appendix → Version History", and update `Current Version:` plus the
   new entries in `data/raw/tabarena_version_history.md` (the CSV files carry no version string).
   Check the candidate's row label and Elo in `data/tabarena.json` (`entries` keys look like `"Model (default)"`,
   `"Model (tuned + ensembled)"`). The selection rule is Elo ≥ TabICLv2 (default) — but add whatever the user asks for.
2. **Gather sources** (all of these, not just the paper): arXiv abstract + HTML (`https://arxiv.org/html/<id>`), the
   code repository (README, LICENSE text, the model source file with size configs, any benchmark adapter), the
   Hugging Face model card and its metadata (`https://huggingface.co/api/models/<org>/<repo>` gives `cardData.license`
   and, with `?blobs=true`, file sizes), and the TabArena PR (`https://github.com/autogluon/tabarena/pulls?q=<name>`)
   which states the declared license, estimator counts, hardware and caveats. Press articles only as pointers.
3. **Write `data/models/<id>.json`** following `data/SCHEMA.md`. Copy an existing record as a template
   (`tabiclv2.json` for an open academic model, `tabpfn-3.5.json` for a licensed commercial one, `kumo-tabular.json`
   for a model that is not on the leaderboard yet). Rules: `id` = filename, lowercase; `tabarena_entry` must equal the
   leaderboard label exactly; numeric sort fields (`parameters_m`, `max_classes`, `max_features`, `max_samples`,
   `num_synthetic_datasets`, `max_context_rows`, `benchmarks.talent.avg_rank/elo`) are plain numbers or `null`;
   `license.commercial_use` ∈ yes/no/restricted/unknown refers to the **weights**; never guess — `null` plus a note;
   every fact traceable to an entry in `sources`. Free-text fields hold dense prose; `key_innovations` is a list.
4. **TALENT.** If the paper (or a third-party paper) reports TALENT numbers, append tables to `data/talent.json`:
   one table per source × metric × task scope, `results` keyed by model id (context baselines keep their own ids,
   e.g. `tabpfn-2.5`, `catboost`), `higher_is_better`, `protocol` text, and `"headline": true` only for the one table per
   source that should become a default column. Add a sentence to `per_model_summary` and the source to `sources`.
   The build derives the short source label from the table id prefix (`<model-id>-paper-…`, `-report-…`, `-blog-…`).
5. **Not on the leaderboard yet?** Add a `tabarena_self_reported` block (see `data/SCHEMA.md`) with the authors' Elo,
   the setup, and a `status` sentence naming the open PR and the date. The page marks the row †, keeps it out of the
   win-rate matrix and the timing scatter, and the official row replaces it automatically after the next fetch
   (build prints a note when that happens — then delete the block, and consider extra records for other sizes/variants).
6. **Validate and build.** `python3 scripts/validate_models.py` (must print OK) then `python3 scripts/build.py`
   (read its `note:`/`WARNING:` lines).
7. **Verify in the browser.** Start the "site" server from `.claude/launch.json` (or `python3 -m http.server 8765`),
   open `http://localhost:8765`, and check: the new row sorts where its Elo puts it; hovering ⓘ shows notes; expanding
   the name shows the full fact sheet with sources; the scatter/heatmap/win-rate figures still render (no console
   errors); the TALENT section shows the new source. Sections below the fold are best inspected with the browser's
   JS tool or by temporarily hiding the table (screenshots of scrolled pages came back blank in the app's pane).
8. **Housekeeping.** Update the state numbers in section 1 of this file and the Claude memory note if something
   non-obvious changed. Do not edit `data/compiled.*` or `data/tabarena.json` by hand.

## 5. Research method that worked

- One `general-purpose` subagent per model, all launched in parallel in the background, each told to read
  `data/SCHEMA.md` first and to write `data/models/<id>.json`; one more agent compiled TALENT tables across all papers
  into `data/talent.json`. Each finished in 8–15 minutes with 20–70 tool calls. The prompt template that worked:

  > You are researching ONE tabular foundation model, <NAME>, for a comparison website. Write a JSON record at
  > `<abs path>/data/models/<id>.json` following EXACTLY the schema in `<abs path>/data/SCHEMA.md` (read it first).
  > Use id "<id>", name "<Name>", tabarena_entry "<Label>".
  > Goal: a careful, source-backed fact sheet. The user cares most about: training details (data, objective,
  > optimizer, steps, batch, hardware, compute/cost); supported number of features / samples / classes; synthetic
  > data generation details; in-context-learning details (context size, large-dataset handling, test-time
  > ensembling, fine-tuning); training and inference speed/cost; licenses for commercial and non-commercial use of
  > code, data/prior and checkpoints (separately); architecture (params, layers, dims, heads, attention scheme, task
  > heads, innovations); differences vs. the predecessor; benchmark results with exact numbers.
  > Sources to use (read all; follow links to paper HTML, GitHub README + LICENSE, HF model card incl. license
  > metadata): <list>.
  > Method: WebFetch the arXiv HTML several times with targeted prompts; WebFetch summarises with a small model, so for
  > exact numbers ALSO curl the HTML into your scratchpad, strip tags and grep (or download the PDF and Read pages).
  > Read the actual LICENSE text; distinguish code vs. weights license. Do not guess numbers: null + note. Numeric sort
  > fields must be plain numbers or null. Validate with `python3 -m json.tool`. Final message: concise summary of key
  > facts and open uncertainties (under 300 words).

- Lessons: WebFetch loses table cells — always confirm numbers from the raw HTML/PDF; arXiv occasionally serves the
  wrong paper for an id (EXAONE's HTML endpoint did) — fall back to the PDF; unauthenticated GitHub API calls hit the
  rate limit quickly — use `raw.githubusercontent.com` for files and read PR bodies early; parameter counts can be
  verified from safetensors headers with two HTTP range requests (done for TabFM: 1,639,444,522) or estimated from
  `.pt` file sizes (fp32 → bytes/4; done for Kumo Tabular); vendors that publish no training recipe (Prior Labs, Stable
  AI, Nums AI, Google, NVIDIA) are represented by `null` fields on purpose; TALENT has no official leaderboard with
  2026 TFMs (checked `github.com/LAMDA-Tabular/TALENT` and `6sy666.github.io/TALENT-Results`), so every TALENT number
  is self-reported per paper and tables must never be merged across sources.

## 7. Page internals (`index.html`)

- No build step for the page itself; it is one file. Data comes from `window.TFM_DATA` in `data/compiled.js`.
- Columns are declared in the `GROUPS` array near the top of the script (group → columns with `id`, `label`, `type`
  num/str/bool/list/link/date, `get(m)`, optional `fmt`, `note`, `title`, `def` = visible by default, `lowerBetter`).
  To add a column, add an entry there; TALENT columns are generated from `D.talent_tables`.
- `PRESETS` defines the "View" dropdown (Essentials, Benchmarks, Architecture & pretraining, Limits/ICL/speed,
  Licensing, Everything). Column visibility, sort and theme persist in `localStorage` (keys `tfm.*`).
- `renderDetails(m)` renders the expanded fact sheet generically (every JSON field appears; unknown top-level keys land
  in "Other fields"), so schema extensions need no page change unless they should become sortable columns.
- Charts are inline SVG/HTML: Elo vs. time scatter (`renderScatter`, log x, label de-collision, hollow marker for †),
  Elo-by-subset heatmap and pairwise win-rate heatmap (`heatTable`, sequential blue ramp, text colour by luminance).
- Provisional (†) handling: `m.tabarena.provisional` from `build.py`; cells get class `prov` and a † with a tooltip.
- Theme tokens live in `:root` with dark overrides under `prefers-color-scheme` and `[data-theme]`; SVG colours use CSS
  classes so both themes resolve at paint time.

## 9. Conventions

- ids: lowercase, hyphenated, versioned (`tabpfn-3.5`, `realtabpfn-2.5`, `mitra-v2`); file name = id.
- `tabarena_entry`: exact leaderboard label incl. variant, e.g. `RealTabPFN-2.5 (tuned + ensembled)`.
- Dates ISO `YYYY-MM-DD` (release = paper/model release, not the TabArena addition date).
- Licenses: `license.code` for the repository, `license.weights` for checkpoints, `license.prior_or_data` for the
  synthetic generator/training data; `commercial_use` / `non_commercial_use` describe the weights.
- TabArena numbers never live in model records (except the provisional block); TALENT numbers never live in model
  records except the author-reported summary under `benchmarks.talent` — the sortable columns come from `data/talent.json`.
